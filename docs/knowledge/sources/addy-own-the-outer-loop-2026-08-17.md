## 一、核心论点

> "工程师需要拥有外循环——对这些系统的问责权。随着 Fable 和 GPT-5.6 等强大模型的出现，这一点只会变得更加重要。"

Agent 拥有杠杆，杠杆创造义务。**必须有人能解释究竟改变了什么、为什么安全、如果错了会发生什么。**

---

## 二、三大核心概念：Quality → Verdict → Answerability

### 2.1 Quality（质量）
- 部署前安装的所有检查
- 这些检查产生**证据（Evidence）**

### 2.2 Verdict（裁决）
- 基于证据做出的最终决策
- "模型写代码，裁决是我的"
- 生产决策：发布、阻止、重定向、收窄、添加护栏、还是拒绝

### 2.3 Answerability（可问责性）
- 如果有人问，我能解释为什么
- 可追溯的决策链条

## 三、Inner Loop vs Outer Loop

### 3.1 系统边界模型

```
┌─────────────── 系统 ───────────────┐
│                                      │
│  输入 → Agent Loop → 输出证据 ──→ [边界] ──→ 人类决策
│                                      │
│  内部：能力（Capability）            │
│  外部：能动性（Agency）              │
└──────────────────────────────────────┘
```

**Inside the System**：
- 能力（Capability）：调查任务、实现计划、测试结果、汇报
- 这就是模型的能力

**Outside the System**：
- 能动性（Agency）：决定、验证、批准、拥有
- 这只有人类能做

### 3.2 四个人类循环（不在 inner loop 里）

1. **Constraints Loop**：设置什么输入、架构、指令、不变量
2. **Sampling Loop**：采样和审查多少输出
3. **Audit Loop**：保留什么证据，确保审计日志有效
4. **Ownership Loop**：拥有生产边界的哪个部分

> "人类不需要在内循环里。但他们需要在正确的决策点上。"

## 四、信任-验证缺口（Trust-Verification Gap）

### 4.1 数据支撑

- **Sonar 2026**：42% 的提交代码是 AI 生成或显著 AI 辅助的
- **GitLab 2026-06**：审查和验证是当前瓶颈；治理通常发生在代码创建**之后**
- **Wharton 研究**：AI 错误时，近 3/4 的人仍然接受，且比无 AI 时更有信心
- **Anthropic RCT**：使用 AI 的工程师在理解测试中比不使用 AI 的低 17 个百分点（50% vs 67%）

### 4.2 核心矛盾

> "我们推动生成速度前进的速度快于推动控制速度前进的速度。"

结果：**信任-验证缺口**。

## 五、Back Pressure as Quality（背压即质量）

> "我们不希望赋予代理它们能行使的最大自主权。我们只希望赋予**刚好足够的**自主权，让我们有足够的背压来阻止、调节、检查它们的工作。"

### 5.1 工程系统的背压信号
- Type checks
- Tests
- Hooks
- Sandbox limits
- Audit logs
- Monitors

只要代理发出同样的信号，我们就能信任普通工程系统提供适当的背压。

## 六、三个隐藏成本

| 成本 | 定义 | 关键数据 |
|------|------|---------|
| **Cognitive Surrender**（认知投降） | 盲目接受 AI 输出 | Wharton: AI 错误时 75% 接受率 |
| **Cognitive Debt**（认知债务） | 理解和记忆的侵蚀 | Anthropic: 理解测试低 17 百分点 |
| **Orchestration Tax**（编排税） | 认知带宽不随代理并行化 | 无法自动化 |

> "棕地系统尤其危险，因为需要审计的系统行为不在代码中，而在疤痕中。"

## 七、Alpha, Decay, Taste（优势、衰减、品味）

### 7.1 定义

- **Alpha**：竞争中最高成就者占据的领先部分，你最高价值的棋步
- **Decay**：通过重复学到的既定模式（平台期）
- **Taste**：在有任何证据之前感知领先或变化的能力

> "从现在开始，品味驱动一切：Alpha 的变化就是品味的变化。Decay 的消退是因为我们开始品味不同的东西。"

### 7.2 品味的来源

- **Paul Graham**：当任何人都能做任何事时，选择做什么更重要
- **Mitchell Hashimoto**：在没有客观指标存在时做出高质量定性判断

### 7.3 品味的操作化
1. 给它起名（从边缘系统提升到意识）
2. 在批评和示例中练习
3. 明确说明理由

## 八、High Agency（高能动性）

能动性阶梯（从低到高）：
```
标记问题 → 调查 → 执行 → 诊断 → 提出方案 → 推荐修复 → 解决
                                          ↑
                                    最高级：辨识力
                              "找到了，不值得修，跳过"
```

**辨识力（Discernment）是能动性的最高阶梯之一**。

---

## 九、Accountability Contract（问责合同）

Addy 提出：每个代码库应附带问责合同，明确声明：
- 接受变更时理解的检查清单
- 决策依据的证据
- 谁对变更负责
- 变更被阻止后的系统状态

## 十、十二根支柱（Twelve Pillars）

棕地是工厂扩展的前沿。棕地系统需要**持久工程（Durable Engineering）**：
1. 将隐式知识转化为显式约束
2. 跨团队和世代保持一致
3. 将知识形式化为测试程序和功能规范
4. 将知识与客观证据绑定
5. 不断将失败转化为学习

> "如果系统没有得到它一直受到的关怀，一切都会崩塌。"

## 十一、核心金句

> "Agent 能写它。但在它到达用户之前，必须有人解释为什么它应该存在、为什么它足够安全、当它出错时你会怎么做。"

> "签名是你名字在工作上的印记，让你感到你能站在被发布的东西后面。技能给你杠杆；问责把杠杆变成信任。"

> "半衰期只是一个发布，但签名的半衰期是一个职业生涯。"

> "每个人都是开发者，但不是每个人都是工程师。"
