## 一、审视确认

### 重新确认的核心要点

**1. AGENTS.md 作为目录而非百科全书的理念仍是最核心的设计原则**
- 约 100 行的 AGENTS.md 作为地图
- 知识库在结构化的 docs/ 目录中
- 渐进式披露（Progressive Disclosure）
- 机械验证：linter 和 CI job 确保知识库最新、交叉链接、结构正确

**2. "人类不写代码"的零手动代码原则仍是最激进的实践**
- 1500 个 PR，平均 3.5 PR/工程师/天
- 7 名工程师，吞吐量随团队增长而增加
- 代理经常单次运行 6+ 小时

**3. 架构约束优先于实现细节**
- 每个业务域的固定层级：Types → Config → Repo → Service → Runtime → UI
- 交叉关注点通过 Providers 统一入口
- 自定义 linter 编码品味不变量

**4. 垃圾回收式技术债务管理**
- 黄金原则编码进仓库
- 定期后台 Codex 任务扫描偏差
- 大多数清理 PR 可在一分钟内审查并自动合并
